# Дизайн: браузерный раннер + бэкенд для пресейва

**Дата:** 2026-07-01
**Ветка:** game
**Проект:** delapovazhnee.ru — сайт группы «Дела поважнее»

## Цель

Добавить к существующему сайту браузерную игру-раннер (пляжный закатный ретро-стиль),
которая открывается в корне сайта, и бэкенд со сбором статистики A/B-теста пресейва
нового сингла. Существующий лендинг (`html/`) не трогаем — он остаётся доступен
по отдельному пути.

## Решения, зафиксированные на брейншторминге

- **Графика:** гибрид — процедурный плейсхолдер-арт (рисуем на canvas) сейчас, с чистой
  точкой подмены на готовые PNG-спрайты позже.
- **Зависимости:** внешний CDN разрешён. Пиксельный шрифт — **кириллический** (напр.
  Pixelify Sans с Google Fonts), т.к. Press Start 2P кириллицу не поддерживает, а игра
  на русском. QR — **server-side** (надёжнее для критичного CTA, без клиентских зависимостей).
- **Деплой:** uvicorn напрямую. `requirements.txt` + `.env`.
- **Адаптивность:** обязательна — телефон и компьютер, обе ориентации.

**Роуты:**

| Путь | Назначение |
|---|---|
| `GET /` | Игра (`templates/game.html`) |
| `GET /home/` | Лендинг — `html/` монтируется как есть через `StaticFiles(html=True)`; относительные пути (`styles.css`, `resources/...`) резолвятся под `/home/`, `index.html` не меняется |
| `GET /static/*` | Ассеты игры |
| `POST /api/event` | Приём событий: `visit`, `game_start`, `game_over`, `cta_view` |
| `GET /go/presave` | Логирует `cta_click` → 302 на `PRESAVE_URL` |
| `GET /qr` | PNG QR-кода (server-side), кодирует `/go/presave?...&src=qr` |
| `GET /admin/login`, `POST /admin/login` | Форма и вход в админку |
| `GET /admin` | Дашборд (под cookie-сессией) |
| `GET /admin/export.csv` | Выгрузка сырых событий (под сессией) |
| `GET /admin/logout` | Выход |

Кнопка «На главную» / «Выход» в игре ведёт на `/home/`.

## 2. Бэкенд, данные, метрики

**Стек:** FastAPI + Uvicorn; **stdlib `sqlite3`** (без ORM, минимум зависимостей; запись
через синхронные эндпоинты в threadpool — трафик кампании это выдержит); Jinja2 для
админки; `qrcode[pil]` для QR; Starlette `SessionMiddleware` для cookie-сессии админа.

**Таблица событий (гибко, без миграций):**

```sql
events(
  id INTEGER PRIMARY KEY,
  ts TEXT,            -- ISO8601 UTC
  session_id TEXT,
  variant TEXT,       -- 'A' | 'B'
  event_type TEXT,    -- visit | game_start | game_over | cta_view | cta_click
  meta TEXT           -- JSON: {"score": N} | {"src": "button"|"qr"}
)
-- индексы: (variant, event_type), ts
```

**Метрики дашборда — по каждому варианту рядом (A vs B):**

- уникальные сессии — `COUNT(DISTINCT session_id)`
- `cta_view` — показы всего + уникальных сессий
- `cta_click` — всего + разбивка `button`/`qr` (из `meta.src`) + уникальных сессий
- **CVR = уник. сессий с `cta_click` / уник. сессий с `cta_view`**
- игр начато / завершено, средний счёт (из `game_over.meta.score`)
- график по дням — простые CSS-бары
- подсказка «лидирует A/B» + оценка уверенности **устойчивая к малой выборке**:
  байесовская вероятность `P(CVR_B > CVR_A)` (Beta-Binomial, точная формула) как основная
  метрика + точный тест Фишера (p-value) рядом; при малом трафике — оговорка «выводы
  делайте осторожно». (z-тест отвергнут: нормальная аппроксимация ненадёжна на малых n.)

**CSV-выгрузка** сырых `events` из админки.

**Авторизация админки:** логин/пароль из env (`ADMIN_USER`, `ADMIN_PASS`), сессия —
подписанная cookie (`SessionMiddleware`, ключ `SECRET_KEY`).

## 3. A/B-механика

- **Назначение варианта — на сервере.** При первом заходе на `GET /` сервер сам бросает
  **50/50**, генерит `session_id` (uuid), кладёт `dp_variant`/`dp_sid` в cookie (на год,
  читаемые из JS) и отдаёт страницу уже с нужным вариантом (через `data-*`-атрибуты).
  Вариант **липнет** к сессии через cookie, при рефреше не меняется. Фронт не рандомит —
  только читает серверный вариант. (Это уточнение к исходному брифу, где вариант кидался
  на фронте: заказчик попросил, чтобы страницу рандомно раздавал сервер.)
- **Вариант A:** CTA (QR + кнопка «Пресейв») на **стартовом экране**, рядом с «Играть».
- **Вариант B:** CTA на экране **Game Over**.
- И кнопка, и QR ведут через `GET /go/presave?v={A|B}&src={button|qr}&sid={sid}`
  → лог `cta_click` → 302 на `PRESAVE_URL`.
- QR кодирует тот же URL с `src=qr` и **вшитым вариантом** (`/qr?v=&sid=` строит целевой
  `/go/presave`-URL server-side). Скан с другого устройства без `sid` — атрибутируем
  по вшитому в QR варианту.
- События на `POST /api/event`: `visit` (1×/сессия), `game_start`, `game_over{score}`,
  `cta_view`. Каждое: `timestamp, session_id, variant, event_type, meta(JSON)`.

## 4. Игра (геймплей + техника)

- Canvas 2D, `requestAnimationFrame`, ~60 FPS, **delta-time** (стабильно на разных экранах).
- Бесконечный раннер: персонаж бежит слева-направо по пляжу автоматически.
- Управление: **пробел / тап**. Одно нажатие = одинарный прыжок, двойное = двойной (выше).
- Препятствия — отдыхающие: одиночка/парочка (одинарный прыжок), с зонтиком (двойной прыжок).
  Спавн справа, движутся навстречу, сбалансированные интервалы, скорость медленно растёт.
- Столкновение → Game Over → рестарт. Счёт = число перепрыгнутых препятствий, в HUD.
- **Гибрид-арт:** сейчас процедурно рисуем персонажа/препятствия/фон из палитры + лёгкое
  покачивание при беге; фон-слои и спрайты грузятся через один модуль — замена на PNG
  без правок игровой логики.

## 5. Визуальный стиль — ТРИ разные айдентики

Проработано через **frontend-design**, зафиксировано в
`docs/superpowers/specs/2026-07-01-visual-directions.md` (authoritative). Реализовать на UI-тасках.
**Не унифицировать поверхности:**

- **Игра** (`/`): летний закатный пиксель (PS1/Sega) — большое дизеренное солнце над морем,
  тёплый градиент неба, параллакс, кириллический пиксель-шрифт (Handjet / Pixelify Sans / VT323),
  холодный циан-акцент на CTA.
- **Лендинг** (`/home`): стиль обложки прошлого сингла — полуночно-синий фон, «горы» из рваной
  бумаги с рукописным текстом, холодная монохромно-синяя гамма. Отдельная таска; нужен файл обложки.
- **Админка** (`/admin`): **обычная, без излишеств** (системный шрифт, светлый фон, простые
  таблицы). Это переопределяет прежний пункт «админка в ретро-стиле».

## 6. Музыка / звук

`static/assets/music.mp3` — loop, старт после первого взаимодействия (учёт автоплей-политики
браузеров), громкость по умолчанию ~0.5, кнопка mute. Короткие ретро-SFX прыжка и game-over —
через **WebAudio (осцилляторы)**, без дополнительных файлов.

## 7. Адаптивность (телефон + компьютер)

**Canvas / рендер:**

- Фиксированная **логическая высота мира** (напр. 360 px); ширина берётся из вьюпорта —
  камера показывает больше/меньше пляжа. Геймплей одинаков на любом экране.
- Учёт `devicePixelRatio` (DPR): backing store × DPR, CSS-размер = вьюпорт → резкость на ретине.
- `image-rendering: pixelated` + масштабирование, близкое к целочисленному.
- **Обе ориентации** (портрет и ландшафт) играбельны; обработка `resize` / `orientationchange`.

**Управление:**

- Десктоп: пробел (и клик мышью).
- Мобайл: тап по экрану; одиночный = прыжок, двойной = двойной прыжок.
- `touch-action: manipulation` + `preventDefault` на `touchstart` — гасим скролл, зум
  по двойному тапу и «резинку», чтобы двойной тап читался как двойной прыжок.

**Интерфейсы (старт, HUD, Game Over, админка):**

- Верстка на `clamp()` / `vmin` / flex — тексты и отступы тянутся под экран.
- Тач-цели кнопок ≥ 44px. QR и «Пресейв» крупные на телефоне и десктопе.
- Дашборд/админка со скроллом и переносом таблиц; A/B-колонки становятся в стопку на мобиле.

**Мета:** `viewport` с `viewport-fit=cover`, отключённый user-scalable, безопасные зоны
(`env(safe-area-inset-*)`) под вырезы телефонов.

## Переменные окружения (`.env`)

- `PRESAVE_URL` — целевая ссылка пресейва (302).
- `ADMIN_USER`, `ADMIN_PASS` — доступ к `/admin`.
- `SECRET_KEY` — подпись cookie-сессии.

## Вне области (YAGNI)

- Правки существующего лендинга `html/` (заказчик переделает сам позже).
- ORM/миграции, тяжёлые графические библиотеки, серверный рендер игры.
- Мультиплеер, аккаунты игроков, серверный лидерборд.
